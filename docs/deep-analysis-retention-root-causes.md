# Y2K-ifier 留存深度分析：根因与逻辑链

本文档做**彻底的原因分析**：不只列「哪里不好」，而是把数据、用户动机、产品逻辑和隐含假设拆开，区分「事实」「推断」和「待验证」，并推到可执行的结论。

## 一、数据：我们究竟知道什么、不知道什么

### 1.1 已知事实（来自你提供的 Analytics）

| 事实 | 数值/描述 |
|------|-----------|
| 过去 30 天安装数 | 325 |
| 过去 30 天卸载数 | 214 |
| 净增 | 111 |
| 安装/卸载与上一周期对比 | 均显示 0.00% 变化 |
| 安装与卸载的日趋势 | 曲线高度同步：安装多时卸载也多，安装降时卸载也降 |
| 按系统：安装占比 | Windows 61%，ChromeOS 20%，Mac 15%，其他 4% |
| 按系统：卸载占比 | Windows 65%，Mac 20%，ChromeOS 14%，其他 1% |
| 地域/语言 | 安装与卸载的分布大致一致，无单一地区/语言异常 |

### 1.2 我们据此做的推断（还不是事实）

| 推断 | 依据 | 可靠度 |
|------|------|--------|
| 「约 66% 的新装用户在 30 天内卸载」 | 214/325 | 需注意：214 次卸载不一定都来自这 325 次安装，可能包含更早安装的用户。但若近似看作同期 cohort，比例数量级可信。 |
| 「用户安装后很快卸载」 | 安装/卸载曲线同步 | 合理：若卸载滞后很久，曲线会错位。同步暗示「新装用户中不少人短期内就卸」。 |
| 「Mac 用户相对更容易卸载」 | Mac 安装 15% vs 卸载 20% | 合理：比例说明 Mac 用户在该 cohort 里卸载占比更高。 |
| 「ChromeOS 用户相对更少卸载」 | ChromeOS 安装 20% vs 卸载 14% | 合理：可能留存更好，或 ChromeOS 用户类型不同（如教育/轻用）。 |

### 1.3 我们目前**不知道**的关键信息

- **从安装到卸载的时间分布**：是当天就卸、3 天内、还是 2 周后？若多数是 24 小时内，问题更偏「首日体验」；若分散在 2～4 周，更偏「缺乏持续理由」。
- **用户是否在卸载前真的「用过」**：有没有打开过 popup、有没有去过选项页、有没有在至少一个网页上看到过 Y2K 效果？若很多人从未看到效果就卸，根因是「价值未触达」；若看到了再卸，根因更可能是「看过了就够了」。
- **留存用户的画像**：留下的人是谁、在什么场景用、为什么没卸？没有对比就难以区分「产品问题」和「用户-产品错配」。
- **Mac/Windows 高卸载的具体原因**：是性能/兼容性问题，还是这两类用户本身就更「试用型」、预期不同？

**结论**：当前数据足以说明「留存差、且与安装强相关、且 Mac 更差」，但**不足以单独区分**两种根本不同的根因（见下文第三节）。深度分析需要在这两种可能性下分别推演，并标出「若要做 A/B 或加埋点，应验证什么」。

## 二、用户到底在「雇」Y2K-ifier 完成什么任务（JTBD）

### 2.1 可能的「工作」与对应留存逻辑

用户安装一个「把网页变复古」的扩展，通常是在完成下面某一类（或混合）「工作」：

| 用户要完成的「工作」 | 典型动机 | 产品若只做到「一套复古 UI」 | 对留存的影响 |
|----------------------|----------|------------------------------|--------------|
| **尝鲜 / 玩一下** | 「想看看现代网页变复古是什么样」 | 看几次就满足了 | **自然终点**：任务完成即离开，除非有下一个任务。 |
| **氛围 / 情绪** | 「摸鱼/怀旧时想要 Y2K 感觉」 | 只提供视觉，没有「场景入口」（如新标签页）或「节奏」（如每日一句） | 依赖用户自己记得「我要开复古」→ **习惯难形成**，留存看缘分。 |
| **身份 / 表达** | 「我是喜欢 Y2K 的人，想展示这一点」 | 没有产出物（图、链接、徽章）、没有分享/社交 | **无法表达身份** → 扩展对「我是谁」无贡献，易被遗忘或卸载。 |
| **效率 / 阅读** | 「在复古风格下读东西更专注/舒服」 | 若真有此需求，理论上会长期开着；但当前没有任何「为阅读优化」的叙事或功能 | 用户不会自然把 Y2K 和「阅读工具」联想在一起 → **该工作未被明确满足**。 |

### 2.2 关键判断：当前产品主要满足的是哪一类？

- **代码与文案实际传达的**：  
  - 默认 `isEnabled: true` → 装完不操作也会在下次加载任意网页时看到 Y2K。  
  - Popup 只有「复古模式 / CRT」开关 + 「打开主题页」。  
  - 商店描述强调「视觉变换」「主题页搜索」，没有强调「每天用」「做图」「分享」。

- **因此**：产品形态最贴合的是 **「尝鲜 / 玩一下」**，其次是 **「氛围」**（但氛围没有和每日触点绑定）。**「身份/表达」** 和 **「效率/阅读」** 几乎未被设计进去。

- **推论**：若多数用户安装时的真实任务就是「玩一下」，那么**高卸载在逻辑上是可预期的**——他们「雇」你完成一次体验，体验完了就「解雇」你。要改善留存，要么：  
  - **让「玩一下」更容易被满足且满意**（减少「没玩到就卸」），要么  
  - **创造新的、可重复的「工作」**（例如「每天在新标签页看到 Y2K」「做一张图发出去」），把产品从「一次性体验」变成「有理由再打开」的东西。

## 三、两种可能的根因（与对应策略）

当前现象同一句「留存差」背后，可以对应两种不同的根因；策略会不同。

### 根因 A：价值没有在「关键窗口」内被触达

- **含义**：很多人**还没真正看到**「网页变 Y2K」的效果，或**没建立**「开关 ↔ 效果」的因果，就离开了。
- **可能表现**：  
  - 装完只看到 popup 里两个开关，不知道要「先去开个网页」；  
  - 默认虽为开，但若用户装完立刻关掉浏览器或先打开的是 chrome:// 等被禁止注入的页，就看不到效果；  
  - 没有演示页、没有「当前页即时预览」，首印象就是「一个带两个开关的小窗口」。
- **若根因主要是 A**：  
  - 策略应偏 **首次触达**：安装/首次打开时自动开演示页、弹窗内小预览、文案明确写「把任意网页变成 90s 风格」、甚至引导「现在打开一个网页试试」。  
  - 成功指标：**首日/首周留存** 是否明显提升；卸载曲线是否从「与安装几乎同步」变为「明显滞后」。

### 根因 B：价值触达了，但「工作」本身是一次性的

- **含义**：用户**已经看到**效果，也觉得好玩，但**任务已经完成**——「看过了」「玩过了」——没有理由再打开。
- **可能表现**：  
  - 安装/卸载曲线同步，但用户其实在卸之前已经用过几天；  
  - 或：用户就是「试几个站就腻了」，因为每站都是同一套 CSS，没有进度、没有收集、没有产出。
- **若根因主要是 B**：  
  - 策略应偏 **创造持续理由**：新标签页（每日触点）、可带走的成果（截图/分享图）、多主题/收集感、或轻量「每日一句/彩蛋」让打开浏览器就有 Y2K 的瞬间。  
  - 成功指标：**D7/D30 留存**、**重复打开 popup/选项页** 或 **新标签页使用次数** 是否提升；卸载是否从「装后很快卸」变为「装后一段时间再卸」或「不卸」。

### 根因 A + B 并存（最可能）

- 现实中很可能是：**一部分人因 A 流失**（没玩到就卸），**另一部分人因 B 流失**（玩过了就卸）。  
- **策略上**：  
  - **先补 A**：成本低、风险小，且能立刻减少「误伤」——本会留的人因为没看懂而离开。  
  - **再补 B**：新标签页、截图/分享、主题等，给「已经玩过一次」的人一个「为什么还要留着」的理由。  
- **验证顺序**：  
  - 若只做 A 后留存明显改善 → A 至少是重要因素；  
  - 若做 A 后首日留存提升但 D7 仍差 → B 占比大，需要 B 类改动；  
  - 若有条件，用简单埋点（如：popup 打开次数、是否打开过选项页、新标签页访问）做分层，看「用过更多入口的人」是否卸得更少。

## 四、心理与行为层：为什么「一套复古 UI」难留住人

### 4.1 奖励类型与可预测性

- **当前体验**：第一次在某个网页看到 Y2K → 有惊喜；第二、第三个站 → 还是同一套字体/按钮/CRT，**惊喜递减**。  
- **行为学**：若「奖励」每次都一样且可预测，习惯很难形成；可变奖励或「下一次可能不一样」才更容易形成重复行为。  
- **对应到产品**：没有「下一站会有什么不同」的预期（无多主题、无每日变化、无进度），**新鲜感一次性耗尽** → 符合「玩一下就走」的推断。

### 4.2 身份与归属

- **当前**：用户没有「用 Y2K 做的东西」可以展示，也没有「Y2K 用户」的可见身份（徽章、分享图、社区）。  
- **结果**：扩展不参与用户的「自我表达」和「社交展示」，在心理上容易被归为「可有可无的小玩具」，卸载时心理成本低。

### 4.3 习惯回路：Cue（提示）→ Routine（ routine）→ Reward（奖励）

- **Cue**：什么会提醒用户「我该打开 Y2K」？  
  - 现在只有「我想起来要开复古」或「我点扩展图标」。没有与**高频行为**（如「开新标签」「每天第一次打开浏览器」）绑定的 Cue。  
- **Routine**：打开 popup → 开关已经开着 → 没有「必须做」的动作。  
- **Reward**：视觉变化在「已开启」的前提下是 passively 获得的，不是「我做了 X 所以得到 Y」的清晰反馈。  
- **结论**：**习惯回路几乎未建立**；产品更多依赖用户主动想起，而不是被环境提示触发。

### 4.4 默认开启（isEnabled: true）的双面性

- **好处**：用户不操作也能在下一个普通网页上看到效果，有机会「偶然发现」价值。  
- **风险**：若第一个被 Y2K 化的页面是用户很在意的站点（如银行、工作后台），可能产生「这什么鬼、关掉」的负面第一印象；或部分用户对「扩展默认改我网页」敏感，立刻卸载。  
- **我们不知道**：多少人是「被默认效果惊喜到」 vs 「被默认效果吓到」。若要做深度分析，可考虑：首次安装时用一次性的「欢迎/演示页」先展示效果，再让用户选择「默认开」或「默认关」，观察留存差异。

## 五、漏斗拆解：我们在哪一阶流失

概念漏斗（无真实数据，仅逻辑）：

1. **商店 → 安装**：325/30 天，无对比基准，不讨论。
2. **安装 → 首次打开 popup**：未知。有人可能装完从未点过图标。
3. **首次打开 popup → 理解「这是干嘛的」**：当前 popup 不解释，理解依赖用户自己试。
4. **理解 → 在至少一个网页看到 Y2K 效果**：依赖用户已打开过普通网页且未禁用注入；若首页是 chrome:// 或已关浏览器，会推迟。
5. **看到效果 → 第二次有意使用**：若没有「第二次」的明确理由（如新标签页、做图），很多人不会回来。
6. **第二次使用 → 形成习惯**：当前无 Cue、无可变奖励、无身份/产出，习惯难形成。

**推断**：  
- 在 **2→3→4** 的任一步都可能流失（价值未触达）；  
- 在 **4→5→6** 流失的，更像是「玩过了，没有下次理由」（根因 B）。  
- 要更彻底的分析，需要至少知道：**打开过 popup 的比例**、**打开过选项页的比例**、**从安装到卸载的中位天数**；哪怕用一次性的「安装后调查」或评论分析也能辅助判断。

## 六、我们当前隐含的假设（与如何验证）

| 假设 | 若假设成立会怎样 | 如何验证或修正 |
|------|-------------------|----------------|
| 「只要 10 秒内看到效果，留存会变好」 | 首日/首周留存提升 | 做演示页/首屏引导后看留存曲线；或 A/B 对比「有演示」vs「无演示」。 |
| 「新标签页能带来每日触点，从而提升留存」 | D7/D30 提升，卸载曲线滞后 | 上线新标签页后看新标签页打开次数与留存相关性；注意部分用户会改回自己的新标签页。 |
| 「一键 Y2K 截图/分享能带来身份与传播，进而留存」 | 分享率、回流、留存提升 | 上线后看截图功能使用率、分享行为（若可测）、以及使用过截图功能的用户留存是否更高。 |
| 「产品本质是 one-time fun，留存天花板低」 | 再怎么做体验优化，长期留存也有限 | 对比同类「趣味/主题」扩展的留存数据（若拿得到）；或接受一定比例的一次性用户，重点提高「玩到」的比例和 NPS。 |
| 「Mac 高卸载是性能/兼容问题」 | 修 Mac 专项问题后 Mac 卸载占比下降 | 在 Mac 上做兼容与性能测试；在商店/反馈中主动问 Mac 用户卸载原因；若有崩溃报告可查。 |

## 七、品类与参照

- **品类**：Chrome 里「主题 / 换肤 / 趣味」类扩展，很多本身就是**低打开频率**：用户设好就忘，或偶尔换着玩。  
- **含义**：  
  - 若 Y2K 的留存显著低于同类中位数，说明我们还有**明显可改进空间**（触达、习惯、产出）。  
  - 若接近同类，则部分流失可能来自**品类共性**，策略可以是：在「接受一定流失」的前提下，把**愿意留的人**的体验做深（新标签页、截图、主题），并尽量让**首日体验**不劝退潜在长期用户。

## 八、总结：深度分析后的结论与顺序

### 8.1 根因归纳

- **表象**：留存低、安装与卸载曲线同步、Mac 更易卸载。  
- **可能根因**：  
  - **A**：价值未在关键窗口内触达（没看到、没理解）；  
  - **B**：价值触达了，但用户「雇」产品完成的是一次性任务，没有设计「第二次」「每天」的理由。  
- **更可能**：A 和 B 同时存在；不同用户分别因 A 或 B 离开。

### 8.2 策略顺序（与之前行动文档一致，但理由更清晰）

1. **先做实「价值触达」（对应根因 A）**  
   - 安装/首次打开：演示页或弹窗内预览、文案写清「把任意网页变成 90s 风格」、可选引导「打开一个网页试试」。  
   - 目标：减少「没玩到就卸」的人，并观察首日/首周留存与卸载滞后是否改善。

2. **再给「持续理由」（对应根因 B）**  
   - 新标签页（每日 Cue + 氛围）；  
   - 可带走成果（Y2K 截图/分享图）；  
   - 场景化文案（摸鱼/梗图/怀旧），强化「什么时候用」。  
   - 目标：让「玩过了」的人有理由留下、再次打开。

3. **平台与体验**  
   - 单独排查 Mac（和 Windows）的兼容与性能，并在反馈/评论中追问卸载原因，验证「Mac 高卸载是否技术问题」。

4. **用数据缩小不确定性**  
   - 若有条件：popup/选项页/新标签页的打开次数、从安装到卸载的天数分布、是否用过截图功能与留存的相关性。  
   - 至少：做 A 前后对比留存；做 B 前后再对比，区分 A/B 的贡献。

### 8.3 一句话

**深度分析后的结论**：留存差既可能因为**价值没在「关键窗口」里被看到**（根因 A），也可能因为**被看到后任务就结束了、没有设计「再来一次」的理由**（根因 B）。当前信息无法完全区分两者，因此**先做 A 再做 B** 是合理顺序；同时用「首日 vs D7 留存」「卸载滞后」「Mac 专项」和（若可能）简单埋点来验证假设，下一轮迭代就会更彻底、更对症。
